## 배경
타이틀 화면의 게임 시작, 스테이지 선택 버튼이 세이브 상태에 따라 다르게 동작해야 한다.
세이브 기능은 아직 없지만, 타이틀 UI가 먼저 필요하므로 **세이브를 읽는 쪽의 규칙**을 먼저 정한다.

## 결정

### 1. 세이브 파일 위치: `Application.persistentDataPath/SaveData.csv`
- Resources 폴더는 빌드 후 **읽기 전용**이라 게임 중에 쓰는 세이브 파일을 둘 수 없다.
- 지금은 읽기만 구현 (`SaveDataStore.Load`). 쓰기는 세이브 기능 구현 때 추가한다.

### 2. 세이브 형식 (Key,Value)
```
Key,Value
LastPlayedStage,2
HighestClearedStage,1
```
| 키 | 의미 |
|---|---|
| `LastPlayedStage` | 진행 중인 판의 스테이지 (1부터). **0 = 진행 중인 판 없음 (엔딩 직후)**. 없거나 숫자가 아니면 0 |
| `HighestClearedStage` | 클리어한 가장 높은 스테이지. 0 = 클리어 없음. **다시 플레이해도 줄어들지 않는다** |

### 3. 세이브를 쓰는 쪽이 지킬 규칙 (세이브 기능 구현 시)
| 시점 | 기록 |
|---|---|
| 스테이지에 들어갈 때 | `LastPlayedStage` = 그 스테이지 번호 |
| 스테이지를 클리어했을 때 | `HighestClearedStage` = max(기존 값, 그 스테이지 번호) |
| **엔딩을 봤을 때** | **`LastPlayedStage` = 0** |

엔딩 때 0으로 기록하지 않으면 타이틀은 "엔딩 직후"와 "엔딩 후 다시 하는 중"을 구분할 수 없다.

### 4. 용어
- **기록 없음:** SaveData.csv가 없거나, `LastPlayedStage`와 `HighestClearedStage`가 둘 다 0
- **진행 중인 판 있음:** `LastPlayedStage` ≥ 1
- **전체 클리어 ("클리어 기록 있음"):** `HighestClearedStage` ≥ 마지막 스테이지 번호

### 5. BTN_GameStart (위에서부터 순서대로 확인)
| 상태 | 동작 |
|---|---|
| 기록 없음 | 페이드 → Intro 씬 |
| 진행 중인 판 있음 | 페이드 → `LastPlayedStage`의 씬 (**엔딩을 본 적이 있어도** 이어서 함) |
| 진행 중인 판 없음 + 전체 클리어 (엔딩 직후) | 팝업 (텍스트 + 예/아니오). 예 = Intro 씬으로 이동 (처음부터 다시), 아니오 = 팝업 닫고 타이틀에 남음 |
| 그 외 (규칙상 생기면 안 되는 상태) | 경고 로그 후 스테이지 1부터 시작 |

예시: 엔딩 → (0 기록) → 게임 시작 = 팝업 → 예 → Intro → 스테이지 1~3 진행 → (3 기록) → 게임 시작 = **스테이지 3**, 스테이지 선택 = 전부 열림

### 6. BTN_StageSelect와 스테이지 해제 규칙
| 상태 | BTN_StageSelect | 열리는 스테이지 |
|---|---|---|
| 기록 없음 | **비활성화** (팝업을 열 수 없음) | — |
| 전체 클리어 | 활성화 | 전부 |
| 그 외 | 활성화 | 1 ~ `HighestClearedStage` (**스테이지 1은 항상 열림**) |

잠긴 스테이지는 이미지를 검은색으로, 버튼을 비활성화한다.

### 7. 스테이지 번호 → 씬 이름
`TitleUI`의 Inspector 스테이지 목록 순서로 정한다 (위에서부터 1, 2, 3...).
스테이지 데이터 테이블을 다시 설계하면 그쪽으로 옮길 수 있다.

## 확정 전에 같이 정할 것
- [ ] "최고 클리어까지만" 규칙에서는 아직 깨지 않은 다음 스테이지를 스테이지 선택으로 들어갈 수 없다. 게임 시작 버튼(마지막 플레이 스테이지로 이동)으로만 진행하는 의도가 맞는지
- [ ] 세이브 쓰기(스테이지 진입·클리어 시점에 기록)를 누가 언제 구현할지

## AI 활용
- 사람이 정한 것: 요청서 전체(버튼 구성, 팝업, 가로 스크롤), "클리어 기록 = 전체 클리어", 해제 범위 "최고 클리어까지", 클리어 팝업 예/아니오와 예 = Intro 씬 (처음엔 스테이지 1이었다가 프롬프트를 정리하면서 Intro로 변경), 세이브 위치 persistentDataPath, 기록 없음 시 BTN_StageSelect 비활성화 (구현 후 추가 요청)
- AI(Claude)가 짚거나 제안한 것: 요청서 문구("최고 클리어의 이전 스테이지까지")의 모호함 질문, Resources 폴더가 빌드 후 읽기 전용이라는 점, 스테이지 1 항상 열림, Key,Value 세이브 형식
- 구현 후 바꾼 것: 사람이 "엔딩 후 다시 플레이하는 경우 게임 시작은 이어서 해야 한다"는 시나리오로 검토 → 처음 구현은 전체 클리어면 무조건 팝업이라 엔딩 후 영원히 팝업만 뜨는 문제 발견 → AI가 "엔딩 시 LastPlayedStage = 0" 규칙을 제안, 사람이 승인
