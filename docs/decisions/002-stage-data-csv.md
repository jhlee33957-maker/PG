## 배경
스테이지 선택 UI가 `StageId`로 씬을 찾아 로드해야 하고, 이후 스테이지별 몬스터 배치(`StageMonster`)도 스테이지를 참조해야 한다.
요구 사항:
1. 코드를 고치지 않고 **CSV 수정만으로** 스테이지를 추가할 수 있어야 한다.
2. 다른 테이블이 참조할 수 있는 **고유 Id**가 있어야 한다.
3. 나중에 BGM, 제한 시간 같은 컬럼이 추가되어도 기존 코드가 깨지지 않아야 한다.

## 선택지

### A. CSV + Resources 폴더
- 장점: 엑셀로 표처럼 편집 가능. 행 추가가 직관적. 다른 테이블과 Id로 연결하기 쉬움. 로드 코드가 단순함.
- 단점: 타입 검사가 없음 (오타가 실행 중에야 드러남). 엑셀 저장 시 인코딩 문제 가능.

### B. ScriptableObject (스테이지마다 에셋 1개)
- 장점: 인스펙터에서 편집, 타입 안전, 씬/에셋을 직접 참조 가능.
- 단점: 스테이지 목록 전체를 한눈에 보기 어려움. 몬스터 배치처럼 행이 많은 데이터를 다루기 불편함.

### C. JSON
- 장점: 중첩 구조 표현 가능.
- 단점: 표 형태 데이터에는 과함. 손으로 편집할 때 실수가 잦음.

## 결정
A. CSV + Resources. (요청자가 지정)

## 기존 설계와의 경계
`AGENTS.md`는 기획서 데이터(문장, 빈칸, 규칙)를 ScriptableObject로 정의한다고 정했다. 두 방식은 역할이 다르다.

| 데이터 | 형식 | 이유 |
|---|---|---|
| 스테이지 목록, 몬스터 배치 등 **표 형태**로 늘어나는 데이터 | CSV | 행 추가가 잦고, 테이블끼리 Id로 연결 |
| 기획서 문장, 빈칸, 규칙 효과 (StageSpec, RuleEffect) | ScriptableObject | 규칙마다 동작(코드)이 달라 타입이 필요 |

`Stage.csv`의 `StageId`와 StageSpec 에셋을 어떻게 연결할지는 기획서 시스템 구현 시 정한다. (후보: CSV에 `SpecName` 컬럼 추가)
