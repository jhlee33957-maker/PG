## 배경
기획서 화면(빈칸 채우기)은 주협이, 규칙 시스템(문장 틀 CSV, 단어, RuleManager)은 강석이 만든다.
두 코드가 만나는 지점을 먼저 정해야 각자 AI로 작업해도 서로 맞는 코드가 나온다.

## 결정

### 1. 별도 씬이 아니라 스테이지 씬 안의 프리팹
- 기획서 ↔ 플레이 전환이 잦고(사망·리트마다), 고른 값을 유지해야 하므로 같은 씬에서 켜고 끈다.
- 주협은 Sandbox 씬에서 `SpecPanel` 프리팹을 만들고, 강석이 각 스테이지 씬에 배치한다.

### 2. 흐름
```
스테이지 시작 → 기획서 (게임 멈춤) → [BTN_Build] → 플레이
                 ↑                                   │
                 └─ 사망 or 리트(BTN_Retry, R키) ─────┤  강석이 레벨 초기화 후 Reopen() 호출
                                                     └─ 클리어 → 다음 스테이지
```
- 다시 열릴 때는 이전에 고른 값이 그대로 채워져 있다.
- 기획서가 열려 있는 동안 `Time.timeScale = 0`. 타이핑 연출은 실제 시간으로 동작한다.
- 리트는 플레이 중에만 동작한다.

### 3. 데이터: 강석의 규칙 데이터를 읽기만 한다
| 데이터 | 주인 | 기획서 UI가 쓰는 방식 |
|---|---|---|
| `Data/SentencesCSV.csv` (Id, Text, Pattern) | 강석 | 문장 틀과 빈칸 위치(`{0}`, `{1}`)를 읽음 |
| `WordId`, `WordTags.DisplayName` | 강석 | 단어와 화면 표시 이름을 읽음 |
| `StageSpec` (ScriptableObject) | 주협 | 스테이지마다: 문장 틀 Id 목록 + 단어 묶음(WordId 목록) |

- 단어 묶음은 모든 빈칸이 같이 쓴다. 같은 단어가 여러 번 필요하면 여러 개 넣는다.
- 어떤 빈칸에든 어떤 단어든 넣을 수 있다. 품사가 안 맞는 문장(`Sentence.IsValid() == false`)은 규칙 쪽에서 처리한다.
- 강석의 파일(CSV 구조, 규칙 코드)은 기획서 UI 작업에서 수정하지 않는다. CSV는 Text/Pattern 값만 수정한다.

### 4. 연결 지점 (SpecPanel)
| 이름 | 방향 | 내용 |
|---|---|---|
| `event Action<IReadOnlyList<Sentence>> Built` | 기획서 → 규칙 | 빌드 시 완성된 문장 목록 (위에서부터 순서대로) |
| `event Action RetryRequested` | 기획서 → 규칙 | 플레이 중 BTN_Retry 또는 R키 |
| `void Reopen()` | 규칙 → 기획서 | 사망·리트 후 레벨 초기화를 마친 뒤 호출 |

처음 합의는 (빈칸 번호, 선택지 ID) 목록이었지만, 강석의 규칙 시스템이 `Sentence`(문장 틀 + WordId 목록)를 단위로 동작하므로 `Sentence` 목록을 직접 넘기는 것으로 바꿨다.

### 5. 선택지 UI 규칙 (끌어다 놓기)
- 기획서가 열려 있는 동안 하단 단어 바가 항상 보인다.
- 단어 바의 단어를 빈칸에 끌어다 놓으면 채워진다 (타이핑 연출). 빈칸에 있던 단어는 단어 바로 돌아간다.
- 빈칸에 쓰인 단어는 단어 바에서 반투명하게 보이고 끌 수 없다.
- 빈칸의 단어를 다른 빈칸에 놓으면 옮겨진다. 놓은 곳에 있던 단어는 단어 바로 돌아간다.
- 빈칸의 단어를 빈칸이 아닌 곳에 놓으면 빈칸이 비고 단어는 단어 바로 돌아간다.
- 모든 빈칸이 채워져야 BTN_Build 활성화.
- 처음엔 "빈칸 클릭 → 하단 단어 클릭" 방식이었으나, 강석의 제안으로 끌어다 놓기로 변경하고 클릭 방식은 없앴다.

## AI 활용
- 사람이 정한 것: 사망·리트 시 다시 정하기, 이전 값 유지, 하단 선택지 + 타이핑 연출, 공용 선택지 묶음, 자유 배치, 사용 중 단어 반투명 + 눌러서 가져오기, 리트 버튼 + R키, 범위 밖 명시, 강석의 데이터는 건드리지 않기
- AI(Claude)가 짚거나 제안한 것: 별도 씬 대신 프리팹, 기획서가 열려 있는 동안 게임을 멈춰야 하는 이유, 이벤트 형식을 미리 맞춰야 하는 이유, 강석 코드 분석 후 넘기는 값을 Sentence 목록으로 변경, RuleManager에 공개 함수가 없다는 점과 리트 시 변신이 남는 문제 발견
- 처음 만든 기획서 UI(자체 StageSpec + 문장 `{}` 표기)는 강석의 CSV 구조와 맞지 않아 폐기하고 다시 작성
