# 결정 기록 (Decision Records)

되돌리기 어렵거나 두 사람의 작업에 모두 영향을 주는 결정을 기록한다.
"왜 이렇게 만들었어요?"라는 질문에 6개월 뒤에도 답할 수 있게 하는 것이 목적이다.

## 언제 쓰나
- 두 사람의 코드가 만나는 인터페이스를 정할 때 (예: 규칙 시스템이 엔티티를 바꾸는 방식)
- 도구, 패키지, 구조를 선택할 때 (예: Input System 도입 여부)
- 기존 결정을 뒤집을 때 → 기존 문서는 지우지 말고 상태를 `대체됨 (→ 00N)`으로 바꾼다

## 규칙
- 파일 이름: `NNN-짧은-제목.md` (번호는 순서대로)
- 상태: `제안` → `확정` (둘 다 동의하면) / `대체됨`
- 결정은 PR로 올리고, 상대가 승인하면 `확정`
- AI에게 선택지 비교를 맡겨도 되지만, **결정과 이유는 사람이 쓴다**

## 템플릿
```markdown
# NNN. 제목

- 상태: 제안 | 확정 | 대체됨 (→ NNN)
- 날짜:
- 작성자:
- 관련 Issue:

## 배경
무엇 때문에 결정이 필요한가?

## 선택지
### A.
- 장점:
- 단점:
### B.
- 장점:
- 단점:

## 결정
무엇을 골랐나.

## 이유
왜 골랐나. 무엇을 포기했나.

## AI 활용
AI에게 무엇을 물었고, AI의 제안 중 무엇을 받아들이고 무엇을 버렸나.
```
